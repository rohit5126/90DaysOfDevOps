## Task 3: Create a Deployment with CPU Requests

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend-deployment
  labels:
    apps: frontend
spec:
  replicas: 1
  selector:
    matchLabels:
      apps: frontend
  template:
    metadata:
      labels:
        apps: frontend
    spec:
      containers:
        - name: frontend-devboard
          image: rohit5126/devboard-frontend:latest
          ports:
            - containerPort: 4173
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              cpu: 100m
              memory: 256Mi
```

## Task 4: Create an HPA (Imperative)


expose deployment as a service-  ` kubectl expose deployment php-apache --port=80 `

kubectl autoscale deployment php-apache --cpu-percent=50 --min=1 --max=10

kubectl get hpa and kubectl describe hpa php-apache

## Task 6: Create an HPA from YAML (Declarative)

```

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: devboard-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: frontend-deployment
  minReplicas: 1
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 5
```
kubectl get hpa

kubectl get hpa -w

kubectl top pods

**behavior**

```
behavior:
    scaleUp:
      stabilizationWindowSeconds: 0
      selectPolicy: Max
      policies:
      - type: Percent
        value: 100
        periodSeconds: 15
      - type: Pods
        value: 4
        periodSeconds: 15
    scaleDown:
      stabilizationWindowSeconds: 300
      selectPolicy: Max
      policies:
      - type: Percent
        value: 10
        periodSeconds: 60
```

The behavior section is split into scaleUp and scaleDown blocks. 
Each block configures:

stabilizationWindowSeconds: The time window to look back at past metrics. The HPA uses this history to pick the safest pod count (highest for down-scaling, lowest for up-scaling).

policies: Specific rules that restrict how many pods can change within a given timeframe.

selectPolicy: The strategy used when multiple policies match. Options are Max (default), Min, or Disabled.
