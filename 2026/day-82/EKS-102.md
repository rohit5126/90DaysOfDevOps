# EKS Networking with Gateway API and Persistent Storage

## Task 1: Understand Gateway API vs Ingress

currently we use the Gateway API instead of the traditional Ingress resource. Research the differences:

| Feature | Ingress | Gateway API |
|---------|---------|-------------|
| API maturity | Stable but limited | GA since Kubernetes 1.26 |
| Traffic splitting | Not supported | Built-in (weighted backends) |
| Header matching | Annotation-dependent | Native HTTPRoute rules |
| Role separation | Single resource | GatewayClass (infra) -> Gateway (ops) -> HTTPRoute (dev) |
| TLS management | Annotation-based | Native TLS config in Gateway listeners |
| Session affinity | Not standardized | BackendTrafficPolicy (with Envoy) |

**Gateway Architecture**

```
[Internet]
    |
[AWS NLB] (created by Envoy Gateway)
    |
[Gateway: gateway]
  |-- Listener: HTTP (port 80)
  |-- Listener: HTTPS (port 443, TLS terminated)
    |
[HTTPRoute: route]
    |
[Service: service:8080]
    |
[Pods: bankapp x2-4]
```

## Task 2: Install Envoy Gateway

Envoy Gateway is an open-source tool for managing application and API traffic that simplifies the operation of Envoy Proxy using standard Kubernetes Gateway API resources

**install using helm**

```
helm install envoy-gateway oci://docker.io/envoyproxy/gateway-helm \
  --version v1.4.0 \
  -n envoy-gateway-system --create-namespace \
  --wait

```

**verify**

```
kubectl get pods -n envoy-gateway-system
use should see a pod in running state
```

## Task 3: Deploy the AI-BankApp with Gateway API

first we need two files one is gateway.yml and another one is network-policy.yml

**gateway.yml**
```
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: envoy
spec:
  controllerName: gateway.envoyproxy.io/gatewayclass-controller

---

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: bankapp-gateway
  namespace: newbankapp
spec:
  gatewayClassName: envoy
  listeners:
  - name: http
    protocol: HTTP
    port: 80
    allowedRoutes:
      namespaces:
        from: Same
---

apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: bankapp-route
  namespace: newbankapp
spec:
  parentRefs:
    - name: bankapp-gateway
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /
      backendRefs:
        - name: bankapp-svc
          port: 80

```

**Network Policy**

```
#default deny all, then allow explicitly
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: newbankapp
spec:
  podSelector: {}
  policyTypes:
    - Ingress
    - Egress

---

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: 
  name: bankapp-policy
  namespace: newbankapp
spec: 
  podSelector:
    matchLabels:
      app: bankapp
  policyTypes:
    - Ingress
    - Egress
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: envoy-gateway-system
          podSelector:
            matchLabels:
              gateway.envoyproxy.io/owning-gateway-namespace: newbankapp
              gateway.envoyproxy.io/owning-gateway-name: bankapp-gateway 
      ports:
        - port: 8080
  egress:
    - to:
        - podSelector:
            matchLabels:
              app: ollama
      ports:
        - port: 11434

    - to:
        - podSelector:
            matchLabels:
              app: mysql-app
      ports:
        - port: 3306

    - to:
        - podSelector:  
            matchLabels:
              app: redis 
      ports:    
        - port: 6379

    - to: []                        # allow DNS resolution
      ports:
        - port: 53
          protocol: UDP

```

**apply the file**
```
kubectl apply -f gateway.yml
kubectl apply -f network-policy.yml
 kubectl get gateway-class
kubectl get gateway -n newbankapp #to get lb address

```

## Task 5: Understand EBS Persistent Storage in Action

EBS volume is used for persisting data in the cluster, Db and AI stateful sets are using EBS storage. AWS EBS supports storage class 'gp2'.

**Key EBS concepts on EKS:**

**WaitForFirstConsumer** -- the volume is created in the same AZ as the pod that claims it
**ReadWriteOnce** -- EBS can only attach to one node at a time (MySQL and Ollama use Recreate strategy because of this)
**gp2** -- Latest AWs EKS cluster suports gp2
**allowVolumeExpansion:** true -- you can grow volumes without recreating them
