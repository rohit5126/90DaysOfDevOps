**What is a fast-forward merge?**
fast forward merge happend when ther is verly less change or 1 file change or 1 commit.

**When does Git create a merge commit instead?**
git creats merge commit when ther are multiple commits or changes in the feature branch.

**What is a merge conflict?**
Merge conflict happens when you change same line in a file in two diffrent branches and then try to merge them. git does not know which line should be kept
in the file and which should be removed, so it craetes merge conflict. we have to manually resolve the conflict to merge the branches.

### Git Rebase

Rebase means jis branch mein I am using the command that branch top commit will be the new head, it does not matter if the reference branch commit is the most latest. rbease rewrites the history and makes the top commit of the current branch as latest commit.

**Why should you never rebase commits that have been pushed and shared with others?**

we should never use rebase because others rely on original timeline and rebase rewrites history and sometimes corrupt repo and timeline.

we use rebase when we want a clean linear commit history in our local without any extra merge commit.

### Squash Commit vs Merge Commit

**What does squash merging do?**
squash merging merge all the extra commits and gets you the data without chnaging the head.

**When would you use squash merge vs regular merge?**
we will use squash merge when we want to get only the data and not the commits and we don't want to change the head. we use regular mergewhen we want a all teh commits.

**What is the trade-off of squashing?**
Harder debugging, merge conflicts, Altered timeline, content loss.

### Task 4: Git Stash
Git stash temporarily saves your uncommitted changes in working directory. imagine you are working on something like adding another feature. you got a call from
a teammate informing there is a P1 ticket regarding a bug. you can't discard all the changes you have made till now on new feature. so you stash your work. start working on the bug. once it is resolved you start from where you left.

git stash

git stash show

git stash list

git stash pop

git stash apply <stash id>

**What is the difference between git stash pop and git stash apply?**
pop works on (LIFO)last in first out system. so the last thing you stashed will be popped out in you working dir. where as apply can get you any saved work in stash list in ay order.you can check list using stash list command.

git stash clear #to remove all the stash list

### Cherry Picking
when you ant to get a specific commit from another branch or specific file and you don't want all the other commits, so you can use cherry pick to get that particular commit.

git cherry-pick <commit_id>

**what could go wromg with cherry-picking**
he most critical flaw of cherry-picking is that it creates duplicate commits with entirely new hashes,
without establishing any historical link between the original commit and the new one.

**Git Ignore**
there are many instance where we work with multiple secret keyfiles that does not need to be pushed to github. but during work people tend to use <git add .> command which stages all the files present in the repo. to avaoid any keys getting pushed we use .gitignore file.
add you secret file in .gitignore and commit .gitignore.nowwhen you try to commit any other changes your secret fles will not be committed.

**pull --rebase**
sometimes you forget to pull latest changes from github and start working on your local. after few hours of commiting you te to know that you do not have the latest files from github. if you do regular pull from origin you will get the fils but also the commits which will be non linear and will be above your latest commit whic is not ideal as this will not show the proper flow. in such cases you use <pull --rebase>. this rewrites history and places all the commit from the github as per linear order. 

git pull origin master --rebase
