### Why was Kubernetes created? What problem does it solve that Docker alone cannot?

it was created to solve the problem of scaling teh application, maintaining the conatiners and to automate deployment.

The Limits of Docker AloneSingle Host Limit: 

* Docker runs on one machine. If that machine dies, all your containers go offline.
* Manual Scaling: You must manually start or stop containers when web traffic spikes.
* No Self-Healing: If a Docker container crashes due to a software bug, it stays down until you manually restart it.
* Fixed Networking: Connecting containers across different servers requires complex, manual network configuration

Problems Kubernetes Solves:
Kubernetes acts as the "brain" or orchestrator for clusters of machines running Docker.

* Multi-Node Orchestration: It pools multiple servers into a single computer resource, deciding exactly where to run containers based on available CPU and memory.
* Automated Scaling: It watches your traffic and automatically spins up more container copies during peaks, then scales them down to save money.
* True Self-Healing: It monitors container health. If a container or an entire physical server crashes, K8s instantly restarts the workload on a healthy server.
* Service Discovery & Load Balancing: It gives containers their own IP addresses and automatically balances network traffic across them.
* Automated Rollouts & Rollbacks: It deploys software updates gradually. If the new version throws errors, K8s automatically rolls back to the previous stable version


### Who created Kubernetes and what was it inspired by?

Kubernetes was founded at Google by engineers Joe Beda, Brendan Burns, and Craig McLuckie, who pitched the project in 2013.
The system was heavily inspired by Borg and Omega, Google’s highly secretive, internal cluster management platforms.

### What does the name "Kubernetes" mean?

The name Kubernetes comes from ancient Greek and means "helmsman," "pilot," or "governor." It represents the person who steers a ship.

## Task 6: Practice Cluster Lifecycle

```

# Delete your cluster
kind delete cluster --name devops-cluster
# (or: minikube delete)

# Recreate it
kind create cluster --name devops-cluster
# (or: minikube start)

# Verify it is back
kubectl get nodes

# Check which cluster kubectl is connected to
kubectl config current-context

# List all available contexts (clusters)
kubectl config get-contexts

# See the full kubeconfig
kubectl config view
```

### Write down: What is a kubeconfig? Where is it stored on your machine?

A kubeconfig file is a configuration file that kubectl uses to securely connect to and authenticate with your Kubernetes clusters.

Default Location: It is stored in a hidden directory in your user's home folder named .kube/config
