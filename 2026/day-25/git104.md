### Task 1: Git Reset — Hands-On
**Answer in your notes:**

**What is the difference between --soft, --mixed, and --hard?**

--soft resets the changes and send it to staging area.
--mixed is a default case which resets and sends it to untracked area
--hard is a destructive case which deletes the changes.


**Should you ever use git reset on commits that are already pushed?**

### Task 2: Git Revert — Hands-On

**git revert**

this commands reverts the particular commit and created another commit mentioning what has been reverted.
the changes made in that particular commit will be reverted.

**How is git revert different from git reset?**

Git revert revert chnages and also create an extra commit. where as reset goes back to that particular commit and removes all the commit above it.

**Why is revert considered safer than reset for shared branches?**

becuase this does not disturb remove any other commits. it reverts the changes made in that particulr commit and craetes a new commit mentioning the revert which help other understand what  is going on. also give ownership to the author. it is safer because linear timeline does not get disturbed.

### git commit --amend
```bash
ubuntu@ip-172-31-16-15:~/devgitops$ git commit --amend -m "deleted again"
On branch master
No changes
You asked to amend the most recent commit, but doing so would make
it empty. You can repeat your command with --allow-empty, or you can
remove the commit entirely with "git reset HEAD^".
ubuntu@ip-172-31-16-15:~/devgitops$ git commit --amend -m "deleted again" --allow-empty
[master 1956a09] deleted again

ubuntu@ip-172-31-16-15:~/devgitops$ git log --oneline
1956a09 (HEAD -> master) deleted again
```

this amends your changes into the last commit instead of creating a new one. this will change the hash id of the commit.
It is primarily used to fix typos in commit messages, add forgotten files, or update code tweaks before pushing.
