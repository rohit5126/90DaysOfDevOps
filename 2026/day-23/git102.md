# Day 23 – Git Branching & Working with GitHub

### Task 1: Understanding Branches

**A branch in GitHub (and Git) is a lightweight, movable pointer to a specific commit in your project's history. 
It allows you to isolate your work from the main codebase**

**we should not commit everything into a main branch as it would disrupt the ogoing worklow and if there is any issue with the latest commit, the man applicaion will be 
affected.**

**Head is a pointer to the latest commit of the branch**

**When you switch branches in version control systems like Git, your working directory and files are dynamically updated to match the commit history of the new branch**

### Task 4: Pull from GitHub
```bash

<<steps
create a repo with same name as in github
connect your local with github using ssh or access token
git remote add origin <url> in local
git remote -v
git pull origin master #to pull master branch

git fetch --all #to fetch all branches
git checkout <branch_name>

steps
```

**git fetch only downloads remote changes to your local repository without altering your files,
whereas git pull downloads those changes and automatically merges them into your active local branch**

### Task 5: Clone vs Fork

**What is the difference between clone and fork?**

Clone downloads your own repo to your local while fork creates independent copy of someone's repo in your github or local

**When would you clone vs fork?**

you should clone when you want to download your repo from remote to local. you should fork when you want to copy any public repo and perform any experiments or
want to work on that repo independently.

**After forking, how do you keep your fork in sync with the original repo?**

git pull upstream main
