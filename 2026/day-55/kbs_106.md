# Persistent Volumes (PV) and Persistent Volume Claims (PVC)

Containers are ephemeral — when a Pod dies, everything inside it disappears. That is a serious problem for databases and anything that needs to survive a restart. 
Today you fix this with Persistent Volumes and Persistent Volume Claims.

## Task1- Create a PersistentVolume (Static Provisioning)

```
apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv 
  labels:
    apps: my-app
spec:
  capacity:
    storage: 2Gi
  accessModes:
   - ReadWriteOnce
  storageClassName: manual
  hostPath:
    path: /mnt/devboard
```

Access modes to know:

ReadWriteOnce (RWO) — read-write by a single node
ReadOnlyMany (ROX) — read-only by many nodes
ReadWriteMany (RWX) — read-write by many nodes

What is the STATUS of the PV?
`Available`

## Task 3: Create a PersistentVolumeClaim

```
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc 
  namespace: dev
spec:
  storageClassName: manual
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 500Mi

```
Both should show Bound — Kubernetes matched them by capacity and access mode

What does the VOLUME column in kubectl get pvc show?
`it shows the ame of pv'

## Task 4: Use the PVC in a Pod — Data That Survives

```
apiVersion: v1
kind: Pod
metadata:
  name: firstpod 
  labels:
    app: myapp
  namespace: dev
spec:
  containers: 
    - name: nginx
      image: nginx:latest
      ports:
        - containerPort: 80

      volumeMounts:
        - name: config-volume
          mountPath: "/mnt"
          readOnly: true 
        - name: data  
          mountPath: /usr/share #this is container path
  volumes:
    - name: config-volume
      configMap:
        name: live-config
    - name: data
      persistentVolumeClaim:
        claimName: my-pvc
```

## Task 5: StorageClasses and Dynamic Provisioning

The core difference is that dynamic provisioning automatically provisions a storage volume on-demand when requested by a PersistentVolumeClaim (PVC), 
whereas manual (or static) provisioning requires a cluster administrator to pre-create the volume before the PVC can use it

Run kubectl get storageclass and kubectl describe storageclass

With dynamic provisioning, developers only create PVCs — the StorageClass handles PV creation automatically.
